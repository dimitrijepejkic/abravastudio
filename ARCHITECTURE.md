# Architecture

## Overview

A static, bilingual marketing site. Astro renders every page to HTML at build time; Cloudflare serves the files.
There is no server code, database, CMS, authentication or form backend.

```
src/
  content.config.ts        Zod schema for the games collection (validated at build)
  content/games/*.yaml     One file per game (localized text, platforms, store URLs, media)
  data/studio.ts           Studio facts; null fields = still to be supplied by the studio
  i18n/locales.ts          Locales (en, sr-Latn) and per-locale metadata
  i18n/routes.ts           THE route table: page keys → localized paths
  i18n/ui.ts               UI dictionaries (sr is type-checked against en)
  config/site.ts           SITE_ENV resolution, site URL, analytics token
  lib/                     games queries, store links (UTM), JSON-LD builders, URL validation
  layouts/BaseLayout.astro <head>: title, description, robots, canonical, hreflang, OG, JSON-LD
  components/              Header, Footer, LanguageSwitcher, StoreButtons, GameCard, ScreenshotGallery, …
  views/                   One view per page type (Home, Games, Game, About, Contact, Press, Privacy)
  pages/[...path].astro    Generates every page × locale from the route table
  pages/404.astro          Bilingual 404 (served by Cloudflare with status 404)
  pages/unsubscribe.astro  Legacy newsletter page (noindex, not in sitemap)
  pages/sitemap.xml.ts     Sitemap with hreflang alternates, from the route table
  pages/robots.txt.ts      Environment-aware robots.txt
public/
  _headers, _redirects     Cloudflare security/caching headers and legacy redirects
  app-ads.txt              AdMob authorization. Must stay byte-identical
  og/, brand/, favicon.*   Generated by `npm run brand`
scripts/                   Brand asset generation, live store-link check
tests/unit, tests/e2e      Vitest and Playwright (+ axe-core)
legacy/                    Pre-v2 assets and the n8n newsletter email template (not deployed)
```

## Routing and localization

`src/i18n/routes.ts` maps page keys (`home`, `games`, `game`, `about`, `contact`, `press`, `privacy`) to paths
per locale. English lives at the root, Serbian under `/sr/` with localized segments:

| Page | English | Serbian |
| --- | --- | --- |
| Home | `/` | `/sr/` |
| Games | `/games/` | `/sr/igre/` |
| Game | `/games/<slug>/` | `/sr/igre/<slug>/` |
| About | `/about/` | `/sr/o-nama/` |
| Contact | `/contact/` | `/sr/kontakt/` |
| Press | `/press/` | `/sr/za-medije/` |
| Privacy | `/privacy/` | `/sr/privatnost/` |

Everything that needs a URL derives it from this table: the catch-all page generator, navigation, the language
switcher, `<link rel="canonical">`, `hreflang` alternates (`en`, `sr-Latn`, `x-default` → English), and the sitemap.
A page therefore cannot exist without its alternate, and the switcher cannot point at the wrong page.

There is no automatic language redirect. Visitors choose a language, and each URL always serves one language.

## Content model

`games` collection (`src/content.config.ts`), one YAML per game:

- `name` (official title, never translated), `storeTitle` (store listing title if different)
- `status`: `in-development | coming-soon | available | unavailable`
- localized `{ en, sr }`: `genre`, `tagline`, `summary`, `description[]`, `features[]`, `keyArtAlt`, `seo.title`,
  `seo.description`, screenshot `alt`
- `platforms.android|ios`: `{ status, url }`, where `url` must be an official store listing URL and is required when
  `status: available`
- media: `icon`, `keyArt`, `screenshots[]` (one may be `featured`), `trailer { youtubeId, title, poster }`
- `links.privacyPolicy`, `links.supportEmail`, `contentRating`, `featured`, `order`

Store buttons are rendered only from `availableStores(game)`: platform `available` **and** a validated URL.
`storeLink()` appends `utm_source=abravastudio.com&utm_medium=website&utm_campaign=<placement>` to Play links so
installs per placement show up in the Play Console acquisition reports.

## Rendering, assets and performance

- Static HTML only. Client JavaScript is three small modules: mobile menu, screenshot lightbox, YouTube facade.
  Each works as plain links without JS.
- `vite.build.assetsInlineLimit: 0` and `build.inlineStylesheets: 'never'` keep every script and stylesheet a
  same-origin file, so the CSP needs no `'unsafe-inline'` or hashes.
- Images go through `astro:assets` (responsive WebP, explicit dimensions). The hero and key art are
  `fetchpriority="high"`, and everything else is lazy. Pixel art uses `image-rendering: pixelated`.
- Fonts are self-hosted from `@fontsource` (Press Start 2P for display, Space Grotesk for body; Latin + Latin-Ext
  subsets for Serbian diacritics), and the two above-the-fold files are preloaded. No third-party requests on load.
- The YouTube trailer loads from `youtube-nocookie.com` only after the visitor presses play.

## Structured data

Built in `src/lib/jsonld.ts`. It describes only what the page shows:

- Home: `Organization` (name, URL, logo, email, country, `sameAs` YouTube + Play developer page) and `WebSite`.
- Game pages: `VideoGame` + `MobileApplication` (name, alternateName, description, genre, platform, content
  rating, publisher, store URL) and `BreadcrumbList`.
- Never: ratings, reviews, offers, download counts, release dates.

## Future products (e.g. a SaaS)

Nothing is built for it now. When one is defined, it should live as a **separate project** (its own app,
repo or Worker on a subdomain such as `app.abravastudio.com`). This site then gains:

- a page key in `routes.ts` (e.g. `product`) with localized paths and a view, for a marketing/landing page;
- a nav entry and footer link;
- optionally a `products` content collection mirroring `games`.

The studio site stays static, so a product's auth, billing and data never share this deployment's attack surface.
